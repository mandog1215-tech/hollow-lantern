Authoritative records

The repository's records outrank this website. If they disagree: the discrepancy is identified, the record and the implementation evidence are inspected, and the website is corrected.

The records the project is run from (in the private development repository; named here so their existence and role are public, without pretending private documents are publicly readable):

  • AGENTS.md — the working rules for anyone developing the game
  • PROJECT_STATE.md — the single source of truth for current state
  • ARCHITECTURE.md — the verified system architecture
  • TESTS.md — what the test suites are and how to run them
  • RELEASES.md — the releases registry this page renders (established 2026-11-01; at the time of this page's publication it stands as an open, unmerged pull request in the repository — its contents are drawn from the same tags and changelog either way)
  • docs/adoption/VISION.md & DESIGN.md — the adopted vision and design record
  • docs/adoption/ROADMAP.md — the milestone plan this site's roadmap renders
  • docs/adoption/KNOWN_ISSUES.md — the issue register behind the testing page
  • The adoption assessment — the Stage 1 baseline audit every figure on this site traces to

The game's source tree is deliberately not reorganized: its layout is load-bearing for the build, the tests, and these documents' references. The organization work happened in documentation and metadata, where it is safe.

This summary is updated at milestone closeouts, in the same pass as the work's report — never ahead of the evidence.
