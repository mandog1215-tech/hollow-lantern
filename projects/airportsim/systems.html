Systems & architecture

How the game is put together — with an evidence grade on every claim.

Grades: Established (holds across varied or long-running conditions) · Demonstrated (a test or reproducible scenario shows the behaviour) · Implemented (code exists; the claim is not yet exercised) · Not implemented. Grades are the 2026-10-31 adoption audit's, applied per system — never upgraded for presentation.

Architecture, as verified at adoption. The simulation core links and tests without any graphics library — that separation is what makes the 162,315-check headless suite possible. The save system is the only writer of the shared state to disk.

A · Simulation foundation

Established

Fixed-step, SDL-independent core

Simulation modules never include SDL headers and link into a headless test binary (an explicit architecture decision in the project's own records). One plain-data global state holds the whole world; seeded random streams make runs reproducible, and the random state is saved with the world.

Established

Saves & version migration

Versioned save format with integrity checks and migrations; fixture saves from five versions back load inside the automated suite, clean under memory-safety instrumentation. The most thoroughly proven system in the game. Detail in section F.

B · Global aviation world

Demonstrated

Airport database & ambient network

4,531 real airports; a seeded ambient network of airlines and fleets keeps the world flying around the player. In the audited session: 1,405 flights airborne on 1,659 routes.

Demonstrated

Weather & world presentation

Live-style weather systems (23 active in the audited session), real METAR reports, country/locale profiles for 232 territories, and the global map with its day/night terminator.

World ⇄ airport. Your airport is a node in the network, not a separate mode: the same flights, weather and clock run through both.

C · Airport operations

Demonstrated

Aircraft & ground operations

A full aircraft state machine — approach, landing, taxi (with pathfinding), stand assignment, turnaround services, departure — at 26 real layouts, with automated or player-operated ATC and ATIS procedures.

Known limitation

ATC final speed control

Documented by the original project itself: approach speed control in the final segment is not implemented. Registered as K7; scheduled in the roadmap's living-world phase.

D · Airport ownership

Demonstrated

The business game

Charges and financial decisions, airline agreements and route proposals, construction and infrastructure, loans, staff, and financial reporting against benchmarks. Exercised in tests and scripted flows.

Implemented — not yet demonstrated

Founding your own airline

The code exists; no complete scripted playthrough has ever been recorded, so today it is a claim, not a proven feature. It earns its grade in the business-depth phase — or gets fixed until it does.

E · Playable roles

Two ways in, one world. Ownership decisions change the airport the operational roles then work in; nothing is a detached mini-game.

Demonstrated

Eight roles, one simulation

Airport owner, pilot, air traffic controller, passenger, ramp worker, gate agent, security worker, airport firefighter — each wired into the same underlying simulation state.

F · Saves & continuity

Established

Versioned saves

Only the save module writes the game state, into the platform's standard per-user location. The format is versioned; every layout change in the project's history shipped with a migration, and fixtures from five versions back still load in the suite. Integrity is checked on load; a save that fails its checks is rejected rather than half-applied.

Not implemented

Tutorial · mod support · live map-data fetching

Named plainly so nobody mistakes them for features. The tutorial's underlying problem is addressed by the roadmap's onboarding phase; mod support and runtime map fetching are open design questions (see the evidence page), not silent decisions.

Grades change only when new evidence is recorded at a milestone gate. If this page and the development record disagree, the record is right.
